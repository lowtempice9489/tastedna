### 코드의 현재 경계

- `SimpleInitialCandidateService`: 본인·제출 완료·Simple 세션에서 최신 Q02 답변과 직접 관측으로 Style Core 초기 후보를 생성한다. `Candidate.sources`는 Q02 근거다. 단일 유효 선택의 `simpleRepresentative`와 `decision.status=DEFERRED`, `finalResult=false`, 빈 최종 결과를 구분한다.
- RESULT-05C: 남성복 Q09 C03:A → 기존 R01 후보, C03:B → 기존 R07 후보의 `CandidateEvidence.positive`만 추가한다. 정의·질문·옵션·EXPLICIT_SELECTION·최신 Q09 revision·관측값을 확인한다. 같은 사실은 해당 후보의 unresolved에서 제거된다. Q09로 후보를 새로 만들거나 반대 후보를 배제하지 않는다.
- `SessionObservationService` / `RawObservationAggregator`: 직접 선택, 비교, 순위와 출처를 보존한다. 순위형의 그룹 내 미선택 관측은 일반 다중선택 미선택과 다르다.
- `SimpleCandidateDiscrimination`: 미검증 속성 차이는 `UNVERIFIED_DIFFERENCE` 등으로 구분하지만 최종 판별은 지원하지 않는다. 지원하지 않는 검증 상태를 승인된 규칙처럼 실행하지 않는다. 일반적인 이미지 근거 준비 상태와 05C의 특정 관계 승인은 별개다.
- 후보 등록은 관계·충분성 승인이 아니다. 상품 스타일/색상 매칭과 상품 정렬은 RESULT의 판별 근거가 아니다.

## 3. 공통 최종 판별 계약

다음은 기존 관측/보안 계약을 보존하는 **구현 제안**이다. 후보별 조건과 승인 버전이 확정되기 전에는 FINAL 분기를 활성화하지 않는다.

1. 본인 제출 완료 Simple만 처리한다. 각 질문의 최신 저장 답변 revision을 기준으로 관측을 수집한다. 질문 사이 revision 숫자가 같아야 한다는 조건을 만들지 않는다.
2. 사실은 정의 ID·질문 ID·그룹/옵션 ID·관측 유형·관측값·근거 유형·revision·순위를 보존한다. 동일 사실의 중복 전달은 제거하되 서로 다른 순위나 질문의 사실을 합치지 않는다. 표시 문자열만으로 후보를 매핑하지 않는다.
3. 승인 관계에는 적용 정의/버전, 정확한 사실 조건, 대상 후보, 지지/상충/그룹 내 비선호 관계, 승인 출처가 필요하다. 미승인 관계는 unresolved다. 기존 Q02 sources와 보조 positive를 구분한다.
4. 상충은 ‘선택하지 않음’이나 이름의 반대가 아니라 **승인된 후보 배제/충돌 관계를 만족한 실제 관측**이어야 한다. 순위형 미선택은 노출된 해당 그룹에만 한정하며, 다른 그룹·일반 다중선택·후보 전체로 확대하지 않는다.
5. 혼합형은 두 Core가 동시에 선택됐다는 사실 외에, 승인된 **결합 자극에 대한 긍정 선호** 및 독립 후보와 구별되는 조건이 필요하다. 결합 자극이 현 문항에 없다면 관측되지 않은 조건으로 남긴다.
6. Attribute-led는 속성 선호와 속성 주도성을 분리한다. Core 근거 부족을 자동 fallback으로 쓰지 않는다. 주도성을 측정하는 관측이 없으면 정책 승인만으로 사실이 생기지 않는다.
7. 후보 평가를 ‘충분조건 성립 / 승인 조건에 따라 불성립 / 조건 또는 근거 미확정’으로 구분하는 방식을 제안한다. 이를 위한 새 공개 API 상태는 필수 아님. 미확정을 false로 바꿔 다른 후보를 남기지 않는다.
8. FINAL 하나의 필요조건: 적용 가능한 승인 규칙 + 실제 근거로 충분조건 충족 + 승인된 충돌 처리 + 인접 후보와의 배타적 구별 + 승인된 표시 콘텐츠. **후보가 하나 남았다는 이유만으로 충분하지 않다.** 여러 후보가 성립하거나 구별에 필요한 조건이 미확정이면 DEFERRED. ID 순서·Q02 선택 순서·상품 수·색상 일치·임의 점수를 tie-break로 사용하지 않는다.
9. 동일 정의/답변 snapshot과 동일 규칙 버전에서는 같은 결과를 반환한다. 사실과 근거의 출력 순서만 안정적으로 정렬한다. 후보 우선순위를 의미하지 않는다. 판별 규칙 버전의 식별·보존 방법은 구현 전 결정할 사항이며 현재 별도 버전 이력이 구현됐다고 가정하지 않는다.
10. 결정 응답에는 사용한 사실 및 부족 조건을 추적 가능하게 연결한다. `simpleRepresentative`와 직접 선호는 기존 계약대로 유지한다. 현재 `decision.status`, `finalResult`의 의미를 바꾸지 않는다.

충분조건 템플릿은 ‘승인된 진입 조건 AND 필수 관측 조건 AND 승인된 구별 조건 AND 충돌 해결 조건’이다. 어떤 문항을 몇 개 요구할지는 아직 승인되지 않았다. “추가 문항 1개면 충분” 같은 수량 기준도 만들지 않는다. 후보별로 필수/선택적/사용 금지 근거를 정해야 하며 모든 Q01~Q10을 의무적으로 소비할 필요는 없다.

## 5. 추가 승인이 필요한 정책과 그 이유

| 최소 결정 | 이유 및 질문을 유지하는 해결 범위 |
|---|---|
| 두 v1.0 설계의 적용 우선순위 | 별도 12개 설계의 favoriteStyleId는 현재 없는 입력. 이번에는 현 Simple 대표 계약 유지. 그 정책을 채택하려면 별도 질문/답변 계약 변경 승인이 필요하므로 본 작업 밖이다. |
| R01/R07 보조 지지의 최종 충분성·경계 | 05C는 실제 관계가 있으나 FINAL 승인은 없다. 우선 두 후보에 대해 필수 추가 사실, 충돌, 동시 후보, R02/R13/R18 등 인접 후보 처리까지 승인하면 작은 구현 단위가 된다. |
| 나머지 Core의 추가 관계 | 정확한 정의/질문/옵션/관측/근거 유형으로 후보 관계를 지정해야 한다. 표시명 또는 실험용 COMPATIBLE/SHARED_SUPPORT를 승격하지 않는다. R01/R02의 공유 근거만으로 구별 불가. |
| Variant·Interaction의 결합 자극 존재 여부 | 현재 이미지 중 실제 조합이 확인되는 자극만 전문가/제품 승인으로 명세한다. 기존 질문에 없으면 복수 Core 선호를 대신 사용하지 않고 해당 후보의 Simple 판별을 보류한다. |
| Attribute-led의 주도성 관측 | Q01/Q03/Q04는 선호를 묻고 우선 원인을 직접 묻지 않는다. 현 비교에서 주도성을 식별할 수 있는 검증된 관계가 없으면 질문 유지 조건으로 독립 판별 불가. ‘Core 실패 시 대체’는 별도 신규 정책이며 자동 채택하지 않는다. |
| R24/R25 유지 및 콘텐츠 차별성 | 원문 자체가 추가 검토 후보다. 독립 결과의 근거/콘텐츠 가치가 없으면 25개를 채우지 않는 범위 결정을 받아야 한다. |
| 최종 하나 선택·상충·보류·대체 경로 | 단일 후보, 복수 충분 후보, 경쟁 후보 미확정 각각의 처리 승인이 필요. 기본 안전 동작은 기존 DEFERRED 유지이며 우선순위 발명은 금지한다. |
| 규칙/콘텐츠 버전과 검증 상태 | CANDIDATE 카탈로그, 관계 승인, 최종 규칙 검증을 별도로 다뤄야 한다. 전역 VERIFIED 변경으로 실험용 관계까지 승인하지 않는다. 정의·정책 버전별 재현 및 근거 추적 방법 결정 필요. |

25개 전체 구현의 차단 요인은 Java 표현력이나 점수 부재가 아니라 **관측하지 않은 결합/주도성, 승인되지 않은 후보 관계와 충분성, 서로 다른 질문 버전의 설계 충돌**이다. 기존 이미지에 필요한 자극이 실제 존재하면 메타데이터 관계 승인으로 일부 해소할 수 있다. 존재하지 않는 관측은 정책 문구만으로 복원할 수 없다. 현재 10문항 고정 조건에서는 해당 후보의 보류/범위 제외가 최소 정직한 해결책이다.

## 6. Java 구현 단계의 최소 변경 범위

이번 문서에서는 코드를 변경하지 않는다. 후보별 승인 전에는 빈 최종 엔진이나 새 서비스 계층을 만들 필요가 없다.

| 기존 대상 | 승인 이후 최소 변경 / 유지할 계약 |
|---|---|
| `SimpleInitialCandidateService` | 최신 관측과 기존 후보별 evidence를 재사용해 승인된 정확한 관계만 추가. Q02 sources·simpleRepresentative·소유권·제출 조건 유지. Q09 보조 관계 재구현 금지. |
| `SimpleCandidateDiscrimination` | 승인된 충분성/구별 조건만 결정적으로 평가하는 분기 추가. 미검증 설정은 기존처럼 FINAL 금지. 대표 스타일로 최종 결정을 대신하지 않음. |
