### 코드의 현재 경계

- `SimpleInitialCandidateService`: 본인·제출 완료·Simple 세션에서 최신 Q02 답변과 직접 관측으로 Style Core 초기 후보를 생성한다. `Candidate.sources`는 Q02 근거다. 단일 유효 선택의 `simpleRepresentative`와 `decision.status=DEFERRED`, `finalResult=false`, 빈 최종 결과를 구분한다.
- RESULT-05C: 남성복 Q09 C03:A → 기존 R01 후보, C03:B → 기존 R07 후보의 `CandidateEvidence.positive`만 추가한다. 정의·질문·옵션·EXPLICIT_SELECTION·최신 Q09 revision·관측값을 확인한다. 같은 사실은 해당 후보의 unresolved에서 제거된다. Q09로 후보를 새로 만들거나 반대 후보를 배제하지 않는다.
- `SessionObservationService` / `RawObservationAggregator`: 직접 선택, 비교, 순위와 출처를 보존한다. 순위형의 그룹 내 미선택 관측은 일반 다중선택 미선택과 다르다.
- `SimpleCandidateDiscrimination`: 미검증 속성 차이는 `UNVERIFIED_DIFFERENCE` 등으로 구분하지만 최종 판별은 지원하지 않는다. 지원하지 않는 검증 상태를 승인된 규칙처럼 실행하지 않는다. 일반적인 이미지 근거 준비 상태와 05C의 특정 관계 승인은 별개다.
- 후보 등록은 관계·충분성 승인이 아니다. 상품 스타일/색상 매칭과 상품 정렬은 RESULT의 판별 근거가 아니다.

## 3. 공통 최종 판별 계약

다음은 기존 관측/보안 계약을 보존하는 **구현 제안**이다. 후보별 조건과 승인 버전이 확정되기 전에는 FINAL 분기를 활성화하지 않는다.

1. 본인 제출 완료 Simple만 처리한다. 각 질문의 최신 저장 답변 revision을 기준으로 관측을 수집한다. 질문 사이 revision 숫자가 같아야 한다는 조건을 만들지 않는다.
2. 사실은 정의 ID·질문 ID·그룹/옵션 ID·관측 유형·관측값·근거 유형·revision·순위를 보존한다. 동일 사실의 중복 전달은 제거하되 서로 다른 순위나 질문의 사실을 합치지 않는다. 표시 문자열만으로 후보를 매핑하지 않는다.
3. 승인 관계에는 적용 정의/버전, 정확한 사실 조건, 대상 후보, 지지/상충/그룹 내 비선호 관계, 승인 출처가 필요하다. 미승인 관계는 unresolved다. 기존 Q02 sources와 보조 positive를 구분한다.
4. 상충은 ‘선택하지 않음’이나 이름의 반대가 아니라 **승인된 후보 배제/충돌 관계를 만족한 실제 관측**이어야 한다. 순위형 미선택은 노출된 해당 그룹에만 한정하며, 다른 그룹·일반 다중선택·후보 전체로 확대하지 않는다.
5. 혼합형은 두 Core가 동시에 선택됐다는 사실 외에, 승인된 **결합 자극에 대한 긍정 선호** 및 독립 후보와 구별되는 조건이 필요하다. 결합 자극이 현 문항에 없다면 관측되지 않은 조건으로 남긴다.
6. Attribute-led는 속성 선호와 속성 주도성을 분리한다. Core 근거 부족을 자동 fallback으로 쓰지 않는다. 주도성을 측정하는 관측이 없으면 정책 승인만으로 사실이 생기지 않는다.
7. 후보 평가를 ‘충분조건 성립 / 승인 조건에 따라 불성립 / 조건 또는 근거 미확정’으로 구분하는 방식을 제안한다. 이를 위한 새 공개 API 상태는 필수 아님. 미확정을 false로 바꿔 다른 후보를 남기지 않는다.
8. FINAL 하나의 필요조건: 적용 가능한 승인 규칙 + 실제 근거로 충분조건 충족 + 승인된 충돌 처리 + 인접 후보와의 배타적 구별 + 승인된 표시 콘텐츠. **후보가 하나 남았다는 이유만으로 충분하지 않다.** 여러 후보가 성립하거나 구별에 필요한 조건이 미확정이면 DEFERRED. ID 순서·Q02 선택 순서·상품 수·색상 일치·임의 점수를 tie-break로 사용하지 않는다.
9. 동일 정의/답변 snapshot과 동일 규칙 버전에서는 같은 결과를 반환한다. 사실과 근거의 출력 순서만 안정적으로 정렬한다. 후보 우선순위를 의미하지 않는다. 판별 규칙 버전의 식별·보존 방법은 구현 전 결정할 사항이며 현재 별도 버전 이력이 구현됐다고 가정하지 않는다.
10. 결정 응답에는 사용한 사실 및 부족 조건을 추적 가능하게 연결한다. `simpleRepresentative`와 직접 선호는 기존 계약대로 유지한다. 현재 `decision.status`, `finalResult`의 의미를 바꾸지 않는다.

충분조건 템플릿은 ‘승인된 진입 조건 AND 필수 관측 조건 AND 승인된 구별 조건 AND 충돌 해결 조건’이다. 어떤 문항을 몇 개 요구할지는 아직 승인되지 않았다. “추가 문항 1개면 충분” 같은 수량 기준도 만들지 않는다. 후보별로 필수/선택적/사용 금지 근거를 정해야 하며 모든 Q01~Q10을 의무적으로 소비할 필요는 없다.

## 5. 추가 승인이 필요한 정책과 그 이유

| 최소 결정 | 이유 및 질문을 유지하는 해결 범위 |
|---|---|
| 두 v1.0 설계의 적용 우선순위 | 별도 12개 설계의 favoriteStyleId는 현재 없는 입력. 이번에는 현 Simple 대표 계약 유지. 그 정책을 채택하려면 별도 질문/답변 계약 변경 승인이 필요하므로 본 작업 밖이다. |
| R01/R07 보조 지지의 최종 충분성·경계 | 05C는 실제 관계가 있으나 FINAL 승인은 없다. 우선 두 후보에 대해 필수 추가 사실, 충돌, 동시 후보, R02/R13/R18 등 인접 후보 처리까지 승인하면 작은 구현 단위가 된다. |
| 나머지 Core의 추가 관계 | 정확한 정의/질문/옵션/관측/근거 유형으로 후보 관계를 지정해야 한다. 표시명 또는 실험용 COMPATIBLE/SHARED_SUPPORT를 승격하지 않는다. R01/R02의 공유 근거만으로 구별 불가. |
| Variant·Interaction의 결합 자극 존재 여부 | 현재 이미지 중 실제 조합이 확인되는 자극만 전문가/제품 승인으로 명세한다. 기존 질문에 없으면 복수 Core 선호를 대신 사용하지 않고 해당 후보의 Simple 판별을 보류한다. |
| Attribute-led의 주도성 관측 | Q01/Q03/Q04는 선호를 묻고 우선 원인을 직접 묻지 않는다. 현 비교에서 주도성을 식별할 수 있는 검증된 관계가 없으면 질문 유지 조건으로 독립 판별 불가. ‘Core 실패 시 대체’는 별도 신규 정책이며 자동 채택하지 않는다. |
| R24/R25 유지 및 콘텐츠 차별성 | 원문 자체가 추가 검토 후보다. 독립 결과의 근거/콘텐츠 가치가 없으면 25개를 채우지 않는 범위 결정을 받아야 한다. |
| 최종 하나 선택·상충·보류·대체 경로 | 단일 후보, 복수 충분 후보, 경쟁 후보 미확정 각각의 처리 승인이 필요. 기본 안전 동작은 기존 DEFERRED 유지이며 우선순위 발명은 금지한다. |
| 규칙/콘텐츠 버전과 검증 상태 | CANDIDATE 카탈로그, 관계 승인, 최종 규칙 검증을 별도로 다뤄야 한다. 전역 VERIFIED 변경으로 실험용 관계까지 승인하지 않는다. 정의·정책 버전별 재현 및 근거 추적 방법 결정 필요. |

25개 전체 구현의 차단 요인은 Java 표현력이나 점수 부재가 아니라 **관측하지 않은 결합/주도성, 승인되지 않은 후보 관계와 충분성, 서로 다른 질문 버전의 설계 충돌**이다. 기존 이미지에 필요한 자극이 실제 존재하면 메타데이터 관계 승인으로 일부 해소할 수 있다. 존재하지 않는 관측은 정책 문구만으로 복원할 수 없다. 현재 10문항 고정 조건에서는 해당 후보의 보류/범위 제외가 최소 정직한 해결책이다.

## 6. Java 구현 단계의 최소 변경 범위

이번 문서에서는 코드를 변경하지 않는다. 후보별 승인 전에는 빈 최종 엔진이나 새 서비스 계층을 만들 필요가 없다.

| 기존 대상 | 승인 이후 최소 변경 / 유지할 계약 |

### 7.4 설계 질문 A/B의 결론과 최소 승인 단위

**A — 결합 착장 자극은 존재한다. 그러나 결합 RESULT 관계는 아직 미승인이다.** R13의 그래픽+전체 착장, R16의 셔츠/니트+운동화, R17의 운동복 요소+일상 착장은 실제 같은 이미지 안에서 선택된다. 이러한 자극을 정확한 후보와 연결하는 것은 가능한 다음 단계다. 반면 두 Q02 스타일의 동시 선택이나 서로 다른 이미지의 요소를 사후 합성하는 방식은 실제 결합 착장 선택이 아니다.

10문항 유지 대안은 (1) R21~R23의 FINAL을 보류하고 확인된 속성 요약만 제공하거나, (2) 사용자 승인으로 해당 후보의 운영 의미를 ‘주도성 확정’이 아닌 ‘속성 비교 선호가 확인된 검토 범위’로 제한하는 것이다. 후자는 후보 의미 변경이므로 이번에 적용하지 않는다. 원래 주도성 의미를 유지하려면 선택 이유/속성 간 절충 등 추가 관측이 필요하며 이번 질문 고정 범위를 벗어난다.

### 7.5 최대 5개 후보 축소: 현재 도달 가능한 수와 승인 과제

현재 정상 질문 계약에서 Q02는 최대 4개다. 06B가 추가하는 M Q09 C03은 단일 A/B이므로 **최대 한 후보만 추가**된다. 중복 제거 후 M 최대 5개, W 최대 4개다. 예: M Q02 `{R02,R03,R04,R05}` + Q09 C03:B → `{R02,R03,R04,R05,R07}`. 따라서 **현재 승인된 진입 관계와 유효 답변만으로 5개를 초과하는 사례는 없다**. 기존 6개 거부 테스트는 미래 확장/비정상 입력 경계이며 정상 문항의 가능한 응답 사례가 아니다.

1. 검토 후보와 **충분성·상충 조건을 통과한 유효 후보**를 구분한다. 최대 5개 제한을 어느 단계에 적용할지 결정한다. 현재 API는 검토 후보도 5개 초과 시 `CANDIDATE_LIMIT_POLICY_REQUIRED`로 거부하므로, 향후 내부 검토 후보를 더 많이 보존하려면 응답 처리도 승인 필요다.
2. 유효 후보가 여전히 6개 이상이면 기본적으로 보류한다. 의미상 중복 후보를 합치거나 Core/Variant 우선순위를 만들려면 각 후보 쌍의 명시적 축소 규칙을 승인받는다. 이것은 지금 없는 규칙이다.

추천 B는 “종합 분류가 검증됐다”가 아닌 **사용자가 승인한 좁은 Simple 운영 충분성**으로 채택하는 안이다. 1km는 제품 비유이며 수치 정확도를 뜻하지 않는다. 전체 25개를 지금 최종화하는 대안은 아니다. A를 선택하려면 Q02 단독 FINAL 허용을 명시적으로 승인해야 한다. C를 선택하려면 위 AND 조합 자체의 승인이 필요하다.

중복 처리: 사실의 정의/질문/옵션/유형/근거/revision을 보존하고 동일 사실은 한 번만 취급한다. 같은 질문 안 여러 옵션은 여러 선택 사실이지 독립된 여러 질문이 아니다. `supportingQuestions`는 출처 집합이며 점수나 통계적 독립성 증명이 아니다. 질문 간 반복 지지도 A/B에서는 설명 보강일 뿐 우선권이 없다. C에서만 지정된 조합 충족 여부에 쓰며 선택 개수로 순위를 만들지 않는다.

### 8.2 최대 5개 축소 대안 및 추천안

먼저 충분성을 통과하지 못한 후보는 **최종군에서 제외하되 초기 후보·근거 응답에는 보존**한다. 승인 관계만 있는 후보와 unresolved만 있는 후보를 같은 추첨 집합에 넣지 않는다. 충분 후보가 1~5개이면 모두 유지, 0개이면 DEFERRED다. 질문 출처가 많은 후보와 한 질문 후보도 선택한 충분성 정책을 통과했다면 자동 우열은 없다.

| 축소 대안 | 6개 이상 / 5번째 경계 처리 | 평가 |
|---|---|---|
| S1. 초과 보류 | 충분 후보 전체를 보존하고 최종 결과를 비운다. CANDIDATE_LIMIT_POLICY_REQUIRED 유지 | 가장 보수적이나 실제 시연에서 계속 보류될 수 있음 |
| **S2. 충분 후보 동등 추출 — 추천 승인안** | 충분 후보 전체에서 중복 없이 5개를 재현 가능한 균등 의사난수 방식으로 추출. 5개 안에서 기존 대표 함수 호출 | ID/응답 순서/질문 수 우선권 없음. 기존 ‘대표 하나 랜덤’과 별개의 **후보군 축소 승인** 필요. 추출 탈락은 비선호·불충분을 뜻하지 않음 |
| S3. 질문 간 교차확인 우선 | 교차확인 후보를 먼저 두고 남은 자리에 단일 질문 충분 후보를 넣음. 경계 동률은 S2 방식으로 남은 자리만 추출 | 출처 종류를 우선순위로 승격하는 새 정책. 관계 밀도가 높은 후보를 편향시킬 위험이 있어 비추천. 승인 전 사용 금지 |

S2 구현 제안: 정렬은 집합 정규화에만 사용하고, 세션·제출 revision·충분 후보 전체·충분성/축소 규칙 버전을 포함한 별도 `pool-reduction` 도메인의 결정적 난수열로 균등 비복원 추출한다. 정렬된 앞 5개나 후보 ID 해시의 숫자 자체를 취향 점수로 해석하지 않는다. 해시 기반 추출 구현 시 범위 변환의 편향 및 동률 처리까지 버전 계약으로 고정한다. 이후 선택된 최대 5개에 기존 `selectValidatedRepresentative`를 호출한다. 07C를 다시 구현하지 않는다.

현재는 근거로 정당화된 상하위 계층이 없으므로 S2에서 6개가 모두 동등하면 모두 같은 추출 자격이다. 정확히 5번째 경계에 동등 후보가 걸려도 사전순으로 경계를 끊지 않는다. S3를 별도 승인한다면 우선군만 6개 이상일 때도 그 군 안에서 비복원 추출해야 한다.

추천 B의 현재 관계만으로는 M에서 Q09 1개 + Q05 1개 + Q10 1개로 **동시 최대 3개**, W는 R13/R17 **최대 2개**다. 따라서 B를 선택하면 당장 S2가 없어도 현재 최종 유효군은 5개를 넘지 않는다. A에서는 남성복 Q02 4개 + Q09 1개 + Q05 1개 + Q10 1개로 최대 7개, 여성복 Q02 4개 + R13/R17로 최대 6개가 가능하다. 향후 관계 확장에도 초과 처리는 필요하다.

### 8.5 사용자가 승인해야 할 최소 결정

1. **충분성 B 채택 여부:** 위 V(R01/R07/R13/R16/R17)의 정확한 관계를 제한적인 Simple 최종 유효성으로 인정할지. 초기 진입 승인과 구별한다. Q02 단독은 직접 선호로 남긴다.
2. **미해석·충돌 처리:** unresolved는 판단에서 제외하고 고지하며, 승인된 충돌이 있는 후보는 해결 규칙 전 보류한다. 현재 없는 충돌 매핑을 만들지 않는다.
3. **동등성:** 충분성 통과 후보는 질문 수·Core/Variant/Interaction 그룹·Q02 유무로 우열을 매기지 않는다. 이질적 후보가 같이 존재해도 비선호로 해석하지 않는다.
4. **축소 S2 채택 여부:** 충분 후보 6개 이상에서 재현 가능한 비복원 5개 추출을 허용할지. 미승인 시 S1 보류 유지. B의 현재 관계에서는 이 승인이 없어도 1~3개 유효군 처리는 가능하다.
5. **활성화 범위·버전:** 승인된 충분성/충돌/축소 정책과 현 이미지 정의의 조합에 명시적 버전을 부여한다. 기존 `simpleRepresentative`는 보존하며 종합 FINAL과 별도로 표시한다. 규칙 변경 전후 결과 유지 정책은 별도 결정하고, 기존 07C 인코딩/알고리즘은 바꾸지 않는다.

- `Q01`=`DIRECT_COLOR_PREFERENCE`, `Q02`=`DIRECT_FASHION_LOOK_PREFERENCE`, `Q03`=`DIRECT_SILHOUETTE_PREFERENCE`, `Q04`=`DIRECT_PATTERN_GRAPHIC_PREFERENCE`, `Q05`=`DIRECT_OUTFIT_PREFERENCE`, `Q06`=`DIRECT_CLOTHING_PREFERENCE`, `Q10`=`DIRECT_FINAL_OUTFIT_PREFERENCE`.
- M `Q08`=`DIRECT_COMPARISON_PREFERENCE`, M `Q09`=`DIRECT_COMBINATION_PREFERENCE`. W `Q08:C01`·`Q09:C04`=`DIRECT_COMPARISON_PREFERENCE`. 이들 `S`의 근거 유형은 `EXPLICIT_SELECTION`이다. W `Q09:C02:A`의 `T`만 `RANKED_COMPARISON_PREFERENCE` / `EXPLICIT_RANKED_SELECTION` / rank 1을 요구한다. 미선택·단순 노출·순위형의 낮은 순위는 이 조건을 대체하지 않는다.
- 아래 표의 **진입조건**만 충족하면 검토 후보다. **제안 충분조건 전체**를 충족해야 B10A의 유효 후보가 된다. 일부 항만 충족하면 FINAL 불가. `NONE`, 일반 미선택, 순위형 미선택에서 긍정 근거를 만들지 않는다.
- `V8 = M ? (S(Q05,D)||S(Q10,E)) : (S(Q05,E)||S(Q06,F))`. 이는 기존 검토의 체크/워크웨어·데님 계열 착장 선호다. Vintage 고유성을 확인했다는 기호가 아니다.
- `SP = M ? S(Q05,C) : (S(Q06,B)||S(Q10,H))`. 기존 R17 스포츠·캐주얼 결합 착장 지지 관계를 재사용한다. 새 R06 해석에는 별도 승인이 필요하다.

### 11.3 A/B 대안과 도달 가능성

| 정책 | 도달 범위 | 이득 / 한계 |
|---|---|---|
| A10A: 현재 직접 시각 충분성 유지 | 기존 10개 | 관측 주장과 자극의 관계를 보존. 나머지 15개에 새 FINAL 없음. |

도달은 **서로 다른 유효 응답에서 각 ID가 최종 후보군에 들 수 있음**을 뜻한다. 한 응답에 25개를 반환한다는 뜻도, 특정 ID가 추첨 대표로 반드시 나온다는 뜻도 아니다. Q02 최대 4개, Q01 최대 5개, Q03 최대 3개, Q04 최대 4개를 유지하며 표의 개별 예시는 이 제한 안에 있다. 각 후보의 양성 예시를 별도로 구성하면 5개 초과를 피하는 경로도 있으므로 단순히 후보 진입만 되고 항상 축소 탈락하는 설계는 아니다.

현재 활성 범위는 M 7개(R01/R03/R05/R07/R13/R16/R17), W 6개(R04/R05/R09/R13/R15/R17)다. 위 B10A 추가 범위는 M 14개, W 15개이므로 **각 성별 21개, 합집합 25개**다. M에서 R04/R09/R15/R21, W에서 R01/R03/R07/R16까지 각각 모두 도달하는 안은 아니다. ‘남녀 각각 25개’가 목표라면 현재 제안만으로는 부족하며 기존 10개 중 성별 전용 관계의 확장도 별도 검토해야 한다. 성별 전용 이미지를 다른 정의에 복사해 해결하지 않는다.

Q02는 전체 엔진의 필수 조건이 아니다. 기존 시각 경로 10개와 새 속성 경로 3개는 Q02 없이 가능하다. 다만 나머지 12개의 **이번 복합 경로**는 직접 스타일 자기표현을 필요로 한다. 자기표현 없이 일반 속성만으로 미관측 Core/혼합 스타일을 생성하는 안은 제안하지 않는다.

혼합형의 선택지는 다음과 같다.

- I1: 위 표의 두 `F`만으로 충분. 5개 혼합형 모두 M/W 도달 가능하지만 한 Q02 내 공존만 관측하며 독립 질문의 보강이 없다. Q02 4개 선택에서 조합 후보가 늘고 자기표현 하나의 영향이 커진다.
- **추천 I2**: 표의 두 `F` + 별도 Q04 또는 착장 선택. 같은 5개 모두 도달 가능하고 사용자가 선택한 맥락이 하나 더 필요하다. 다만 보강이 공통 속성 또는 한쪽 스타일만 지지할 수 있으며 실제 결합 착장 선호를 증명하지는 않는다. 질문 수를 점수로 계산하지 않는다.

속성형은 원래 의미를 유지하면 현재도 불가능하다. 위 표는 ‘두드러진’이라는 말도 중요도 수치나 타 속성 대비 우위가 아닌 **서로 다른 질문에서 관련 선호가 확인됨**으로 제한하는 대안이다. Color-led의 M 경로는 독립 색상 비교가 없어 제안하지 않는다. Surface-led는 체크 패턴의 확인된 활용에 국한하며 소재 촉감 같은 미관측 속성을 포함하지 않는다.

### 11.4 6개 이상 후보와 기존 선정 연결

유효 ID는 집합으로 만든 뒤 기존 `reduceEquivalentValidatedCandidates`와 `selectValidatedRepresentative`에 순서대로 전달한다. 충분성의 종류, 질문 개수, 같은 속성의 반복 횟수로 우선순위를 만들지 않는다. 직접 시각 후보와 복합 가능성 후보를 **동등한 제품 후보**로 함께 추첨할지 명시적 승인이 필요하다. 동등성을 승인하지 않으면 두 집합을 임의로 합쳐 S2를 실행하지 않고 새 정책을 기다린다.

실제 가능한 초과 예: M Q02=`R08,R05,R11,R07`, Q04=`P03`, Q05=`D`, Q08 C01=`B`, Q09 C02=`A`·C03=`A`, Q10=`D`. 현재 관계 R01/R13과 B10A R08/R14/R19/R23/R24, 총 7개가 충분성을 충족한다. 서로 다른 Q09 그룹은 동시에 응답 가능하고 Q02 4개 제한도 지킨다. 나머지 Q01/Q03/Q06/Q07 등은 계약에 맞게 채우되 별도 충분성을 추가하지 않는 예를 구성할 수 있다. 같은 V8/Q04 사실이 여러 후보에 쓰여도 후보별 추첨권은 하나다. 기존 S2로 5개를 재현 가능하게 고르고 기존 대표 선택으로 하나를 고른다.

전체 후보 ID 집합·세션 ID·제출 revision·판별 버전이 계산에 반영되어야 한다. 복합 규칙 추가 시 `RULE_VERSION`을 갱신하되 SHA-256 인코딩, S2 및 대표 알고리즘은 재작성하지 않는다. 버전 변경 후 과거 제출을 새 규칙으로 재계산하면 결과가 달라질 수 있음을 명시한다. 같은 버전 내 재조회 안정성과 과거 버전 결과 영구 보존은 다른 계약이다.

### 11.5 한 번에 승인할 최소 결정

추천 승인 묶음은 **표의 B10A 전체 조건 + 혼합형 I2 + 제한된 의미 표시 + 기존/신규 유효 후보의 동등 S2 참여**다. 다음을 함께 확인해야 구현 범위가 닫힌다.

1. 6개 Core는 자기표현과 보강 선호의 조합으로, R14는 패턴 빈티지 가능성으로, 5개 혼합형은 공존 기반 혼합 가능성으로 FINAL을 허용한다. 이는 원래 독립 착장 증명의 대체 정책임을 인정한다.
2. R21~R23의 운영 의미를 표에 기재한 반복·비교 속성 선호로 제한한다. ‘취향을 주도함’, ‘소재 촉감 선호’라는 미관측 주장은 금지한다. 원래 의미를 유지하는 선택이면 세 ID는 활성화하지 않는다.
3. 새 유효 후보와 기존 시각 후보는 동등하며 중복 스타일 가족도 자동 병합하지 않는다. 가족 간 유사성 때문에 확률 분포가 달라질 수 있지만 이를 보정할 가중치는 도입하지 않는다.
4. 이번 도달 목표는 M/W **합집합 25개**임을 선택한다. 남녀 각각 25개가 필수라면 이 승인 묶음만으로 완료 처리하지 않는다.

추가 관측 없이 불가능한 것은 원래 의미의 주도성, 실제 한 착장에 대한 미관측 혼합 선호의 입증, 그리고 현재 제안에서 빠진 성별별 경로다. 정책 승인은 없는 관측을 생성하지 않는다. 승인 전에는 위 15개에 어떤 활성 FINAL 규칙도 추가하지 않는다.

### 11.6 승인 후 정확한 Java 변경 및 검증 범위

1. `SimpleInitialCandidateService.find`의 현재 Raw 사실 수집 이후, 후보 카탈로그 JPA 조회 이전에 표의 초기 진입조건을 연결한다. 기존 `addOutfitEntrySupport` / `addOutfitSource`의 최신 답변·정의·이미지 검증을 재사용하고, 일반 속성/비교는 실제 정의와 Raw 유형을 확인한다. 새로운 Repository나 규칙 엔진은 필요 없다.
2. 기존 `CandidateEvidence.positive`에 조건을 구성하는 실제 `Source`들을 보존한다. R14/혼합형의 Q02 원천 옵션은 실제 R08/R01 등의 ID 그대로 기록한다. 후보 ID로 바꾼 가짜 Q02 선택을 만들지 않는다. `Candidate.sources`의 기존 직접 Core 매핑과 `simpleRepresentative`는 그대로 두므로 Q02 없는 후보 또는 합성 후보의 sources는 비어 있을 수 있다. 연결된 긍정 사실만 unresolved에서 제거한다.
3. `SimpleCandidateDiscrimination.reviewInitialCandidates`에서 기존 `sufficientVisual`은 유지하고, 후보별 **전체 긍정 근거 집합**에 대한 표의 AND/OR 충족 판정을 추가한다. 현재 `additional.stream().anyMatch(...)`에 조합의 한 조각을 넣어 충분성을 통과시키면 안 된다. Q02 단독 Core, Q02 쌍 단독 I2, 속성 단독은 모두 불충분하다. 기존 candidate-specific conflict 차단을 유지하며 새 충돌 관계는 만들지 않는다.
4. 동일 사실은 정의·질문·optionId·관측/근거 유형·최신 revision·rank로 중복 제거한다. Q02의 두 옵션은 한 질문의 두 직접 선호이지 독립된 두 질문 근거가 아니다. 서로 다른 질문의 개수는 설명용이며 점수로 쓰지 않는다.
5. 기존 `CandidatePoolReview.validatedCandidateIds` → `reduceEquivalentValidatedCandidates` → `selectValidatedRepresentative` → `Decision` 연결을 재사용한다. 응답 필드 추가 없이 실제 근거, FINAL 유무, 대표 ID를 보존한다. 제한된 결과 설명이 기존 UI의 확정 문구와 충돌하는지는 후속 구현 시 해당 표시만 확인하며 전체 화면을 재설계하지 않는다.
6. 기존 `SimpleInitialCandidateServiceTest` / `SimpleCandidateDiscriminationTest`에 15개 조합의 최소 양성 예와 AND 한 항 제거 시 보류, 다른 정의·옵션·revision·rank, Q02 미선택 속성 경로, 중복 사실, 위 7개 초과 사례, 순서/재조회 불변성, 기존 10개 회귀를 필요한 범위로 추가한다. 서비스 규칙에 가짜 이미지/승인 관계를 넣지 않는다.

이번에는 V13/V17/V18/V19의 실제 옵션·선택 제한과 현재 Java 메서드/관측 유형을 정적으로 대조했다. 앞 절의 W Q09 C04나 Q08 C01에 `C`까지 적힌 역사적 예시를 실행 조건으로 재사용하지 않는다. 실제 두 그룹 모두 A/B뿐이며 본 표는 존재하는 옵션만 사용한다. Java·테스트·SQL·이미지는 변경하지 않았고 빌드·DB·브라우저 검증은 실행하지 않았다.


## 12. RESULT-10B — 승인된 복합 관측 조건 적용

10B 사용자 지시로 11절의 정확한 복합 조건과 I2, 제한된 의미, 동등 S2 참여를 적용했다. 11절은 당시의 제안 기록이며 이 절이 구현 상태를 갱신한다. 기존 직접 시각 10개와 복합 15개를 구분하고, 복합 충분성 충족 시 `CandidateEvidence.status=SIMPLE_COMPOSITE_PREFERENCE_INFERENCE`로 표시한다. 실제 Source의 질문·옵션·유형·revision·rank는 보존하며 가짜 혼합 착장 관측을 생성하지 않는다.

판별 버전은 `simple-B-v4-composite10B/S2-SHA256-v1/representative-SHA256-v1`이다. S2/대표 알고리즘과 `simpleRepresentative` 의미는 유지한다. 도달 범위는 남녀 합집합 25개(각 21개)이며 남녀 각각 25개라는 뜻이 아니다. 기존 마이그레이션의 질문·관측 규칙과 실제 응답 검증기를 이용한 저장 답변→Raw→FINAL 테스트로 확인한다. 실제 DB·브라우저 및 제한된 의미의 화면 설명 검증은 후속 통합 범위다.
