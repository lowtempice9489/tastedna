# TasteDNA Simple V1 제출 상태

작성 기준: 2026-11-08, 작업 15-F4까지의 구현 및 검증 결과. 이 문서는 기존 결과를 정리하며, 작성 과정에서 테스트나 DB 적용을 새로 실행하지 않았다.

FORM은 TasteDNA를 시연하는 데모 쇼핑몰이다. TasteDNA는 FORM 회원과 연결된 취향 테스트 기능이며 별도 회원 서비스가 아니다. 제출 범위는 남녀 Simple의 응답 기록, 직접 선호·대표 스타일 표시, 등록 상품 속성 기반 매칭 및 저장 기록 재조회다.

## 구현 및 검증 수준

| 기능 | 실제 구현 범위 | 확인된 검증과 한계 |
|---|---|---|
| FORM 회원 인증·세션 연결 | FORM 로그인 회원의 소유 세션만 조회·변경하도록 보호 | 기존 회원 인증 통합 테스트 성공 결과를 재사용. 15-F4에서 실제 로그인 상태, 로그아웃, 재로그인 및 본인 기록 복구 확인. 타인 접근은 기존 자동 테스트 범위이며 이번 시연에서 재현하지 않음 |
| 남녀 Simple Q01~Q10 | 각각 10문항, 정의별 단일·복수·비교·순위·NONE 배타 선택 | 15-A2·15-A3 등의 기존 남녀 대표 브라우저 흐름 확인 결과를 재사용. 일반 미선택을 비선호로 확대 해석하지 않으며 순위는 승인된 비교 그룹 안에서 보존 |
| 응답 저장·복구·제출 | 최신 저장 답변 조회, 수정·revision 충돌 검사, 새로고침 복구와 제출 후 수정 차단 | 기존 Java·Node 및 실제 브라우저 대표 흐름 검증. 15-F4에서는 새 응답을 만들지 않고 완료 세션 재사용 |
| 직접 선호 스타일 | 실제 Q02 선택을 표시하고 복수 선택은 동등하게 유지 | 15-F4 남성복 미니멀·캐주얼, 여성복 미니멀·로맨틱 표시 확인. 임의 대표 순위나 점수 없음 |
| Simple 대표 스타일 | 제출 완료 최신 Q02의 유효한 단일 스타일만 `simpleRepresentative`로 반환. 복수·근거 부족은 `null` | 15-R2 관련 Java·Node 통과, 15-R3 남녀 단일·복수·근거 부족 및 재조회 Node 검증. 단일 스타일 완료 기록의 실제 브라우저 확인은 미실행 |
| Q01·Q02 상품 매칭 | Q02 스타일 일치가 필수이며 Q01 색상 일치는 추가 근거. 이미지 URL·RESULT 유형은 매칭 조건이 아님 | 기존 Java 검증과 15-F4 실제 카드 근거 표시 확인. 남성복 10개·여성복 17개 매칭 목록의 표시 수 확인. 이는 해당 시연 응답의 결과이며 모든 사용자에게 고정된 수가 아님 |
| 의류 범위 필터 | 남성복은 MENS·UNISEX, 여성복은 WOMENS·UNISEX 허용. 미분류 제외 | 관련 자동 테스트로 경계 검증. 등록 카탈로그에는 UNISEX가 없으므로 실제 등록 상품과 지원 정책을 구분. 15-F4에서 상품 범위 속성의 실시간 API·DB 대조는 미실행 |
| 색상 일치 우선 배치 | 스타일 후보 중 색상 일치 상품을 먼저 표시. 불일치·미등록 상품도 유지하고 그룹 내부 기존 순서 보존 | 15-T3B3 Java 매칭 테스트 10개 통과. 15-F4 남녀 화면 앞쪽의 색상 일치 근거와 남성복의 이후 스타일 단독 근거 확인. 전체 목록의 실시간 속성 대조는 미실행 |
| 상품 더 보기 | 최초 최대 4개, 이후 네 개씩 공개 | 15-F4 남녀 최초 4개 확인, 남성복 더 보기 4→8개 확인. 상품명·가격·이미지·근거는 기존 API 응답 사용 |
| 마이페이지 기록·리포트 재조회 | 본인 진행·완료 기록, 이어하기, 완료 리포트·상품 연결 | 기존 자동 테스트와 15-F4 남녀 완료 기록 재조회 및 재로그인 후 동일 여성복 리포트 복구 확인 |
| 인증 만료 HTTP 401 | 보호 요청의 401은 공통 로그인 안내로 전달하고 회원·세션 메모리와 화면을 정리. 일반 보조 조회 실패는 리포트 유지 | 15-F3 수정 전 결함 재현 후 관련 Node 5개 통과. 15-F4 다른 탭의 정상 로그아웃 후 기존 화면 보호 요청에서 로그인 안내·회원 및 리포트 제거 확인. 별도 비인증 HTTP 요청으로 `preference-summary`, `initial-candidates`, `matched-demo-products` 모두 401 확인. 보조 API 요청 도중 만료되는 정확한 타이밍 및 일반 서버 오류의 실제 브라우저 재현은 미실행 |

리포트는 취향 요약 가까이에 상품을 배치하고 상세 선택 기록은 기본 접힘으로 유지한다. 15-F4에서 해당 표시를 확인했으며 확인한 브라우저 로그에는 JavaScript 오류가 없었다.

## 제출 판단과 검증의 경계

- 15-F4 확인 범위에서 제출을 막는 기능 결함은 발견하지 않았다. 모든 환경·입력에 대한 무결함을 의미하지 않는다.
- MySQL V25·JPA·회원 인증 통합은 사용자의 로컬 재실행 성공 보고를 재사용한다. 15-F4에서 DB 이력을 다시 조회하거나 변경하지 않았다.
- FORM 상품 100개는 기존 구축·검증 결과를 기준으로 한다. 등록 수, 화면별 매칭 수, 독립 이미지 수는 서로 다른 개념이다.
- Java 21의 `compileJava --offline`은 15-F4에서 `BUILD SUCCESSFUL`과 `UP-TO-DATE`를 확인했다. 전체 테스트를 새로 실행한 결과가 아니다.
- 대표 스타일의 단일 선택 실제 시연, 보조 요청 도중 인증 만료, 실제 서버 오류 시 리포트 유지, 실시간 상품 범위 대조는 추가 실사용 확인 대상으로 남긴다.

## 미완성 또는 범위 제외

| 항목 | 제출 범위와 구분 |
|---|---|
| R01~R25 최종 종합 RESULT | 최종 승인 판별 규칙은 미완성. 종합 판별은 `DEFERRED`를 유지하며 Simple 대표 스타일을 `FINAL`로 승격하지 않음. R13~R25를 강제로 확정하지 않음 |
| Deep 25문항 | V1 제공 범위 밖. 구현 완료나 이용 가능으로 표시하지 않음 |
| 외부 쇼핑몰 운영 연동 | 회원 식별·인증·상품 시스템 및 운영 환경에 대한 별도 통합 필요. 범용 SDK·플러그인·자동 연동 완료를 주장하지 않음 |
| 주문·결제 | FORM은 전시용 데모이며 실제 주문·결제를 제공하지 않음 |

추천 정확도·매치율·임의 점수는 제공하지 않는다. 직접 선택 스타일, Simple 대표 스타일, 미확정 종합 RESULT는 서로 구분한다.

## 제출 시연 순서

FORM 로그인 → Simple 시작 → 응답 제출 → 취향 리포트 → 추천 상품 → 마이페이지 결과 재조회.

1. FORM 회원으로 로그인한다. TasteDNA용 별도 계정을 만들지 않는다.
2. TasteDNA에서 의류 → 남성복 또는 여성복 → Simple을 선택한다.
3. 서버 정의의 선택 규칙에 따라 10문항에 응답하고 저장·제출한다.
4. 리포트에서 실제 Q02 직접 선호를 확인한다. 유효한 단일 스타일은 Simple 대표 스타일로, 복수는 동등한 선호로 표시한다. 종합 RESULT는 미확정이다.
5. Q02 스타일 및 Q01 색상 근거가 있는 상품 카드와 더 보기를 확인한다. 연결 상품이 없으면 빈 상태를 표시한다.
6. 마이페이지에서 해당 저장 기록을 다시 열어 동일 리포트와 상품을 확인한다.

짧은 재시연에서는 기존 완료 세션을 재사용할 수 있다. 단일 대표 스타일 시연은 단일 Q02 선택 완료 기록이 있을 때만 수행하며 기존 답변을 임의 변경하지 않는다.

## 최소 실행 조건

상세 명령과 비밀번호의 로컬 입력 방법은 [README 실행 절](../README.md#실행)을 따른다. 외부 연동 경계는 [기존 연동 가이드](storefront-integration.md)를 참조한다.

- Java 21, 프로젝트 Gradle Wrapper, MySQL 8.4를 사용한다. Spring Boot 4.1.1 의존성은 기존 프로젝트 설정을 따른다.
- 프로젝트 루트에서 실행하며 `gender/` 이미지 자산을 함께 유지한다.
- 독립 `tastedna_test` DB와 그 DB 전용 권한 계정을 준비한다. `SPRING_DATASOURCE_URL`을 `jdbc:mysql://localhost:3306/tastedna_test?connectionTimeZone=UTC`로 지정한다. 기본 개발 DB `tastedna`로 시연 검증하지 않는다.
- 기존 `DB_USERNAME`, `DB_PASSWORD` 환경변수를 사용한다. 비밀번호·토큰·개인 계정 정보를 문서나 Git에 기록하지 않는다.
- `member-auth` 프로필, `127.0.0.1:8081`로 실행한다. 로컬 HTTP에서만 `AUTH_COOKIE_SECURE=false`를 사용하고 HTTPS에서는 `true`를 유지한다.
- 기동 시 Flyway V1~V25의 미적용 이력이 적용되고 JPA가 스키마를 검증한다. 기존 이력 수정·DB 초기화는 하지 않는다.
- 서버 기동 로그와 실제 HTTP 응답을 확인한다. Gradle 종료 문구만으로 실행 중이라고 판단하지 않는다.

## 개발공간 6 — 추가 검증 (2026-11-09)

### Simple 대표 스타일 및 결과 재조회

FORM 회원 로그인 후 남성복 Simple 10문항을 완료했다.
Q02에서 R01 미니멀만 선택한 완료 세션으로 다음을
실제 브라우저에서 확인했다.

- Simple 대표 스타일 '미니멀' 정상 표시
- Q01 블랙·화이트/아이보리 선택 기록 표시
- Q02 스타일과 Q01 색상 근거를 이용한 상품 카드 표시
- 종합 RESULT 미확정 안내 유지
- 마이페이지 완료 기록 표시 및 결과 리포트 재조회 성공

이번 검증은 단일 대표 스타일의 남성복 시연 사례이며,
모든 스타일과 입력 조합의 정상 동작을 보장하지 않는다.

### 보조 API 오류 대응 회귀 테스트

`dev/verification/form-flow.test.mjs`에 HTTP 500 오류
회귀 테스트를 추가했다.

- initial-candidates 오류 시 기본 리포트 유지
- matched-demo-products 오류 시 기본 리포트 유지
- 일반 서버 오류를 인증 만료로 잘못 처리하지 않음

IntelliJ에서 해당 테스트 파일 전체 17개 통과,
실패 0개를 확인했다.

실제 서버의 HTTP 500 응답을 브라우저에서 재현한
검증은 아니며, Node.js DOM 대역 테스트 결과다.

### 상품 매칭 및 카탈로그 자동 테스트

IntelliJ에서 다음 Java 테스트 클래스를 각각 실행했다.

- DemoProductMatchServiceTest: 전체 통과, 실패 0개
- DemoCatalogTest: 전체 통과, 실패 0개

상품 매칭의 선택 근거, 색상 우선 배치, 의류 범위
필터 및 카탈로그 등록 계약에 관한 기존 회귀 테스트다.

이는 사용자 로컬 실행 보고에 근거하며, 이번 작업에서
실제 MySQL 전체 상품 데이터를 별도 대조하지는 않았다.

### 제출 범위 판단

Simple V1의 주요 사용자 흐름과 위 회귀 검증 범위에서
새로운 기능 결함은 발견되지 않았다.

종합 RESULT 최종 판별, Deep 및 외부 쇼핑몰 운영 연동은
기존 문서에 명시된 미완성 또는 범위 제외 상태를 유지한다.
