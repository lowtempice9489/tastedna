# TasteDNA Question & Answer Contract

Status: DRAFT
Scope: Non-AI question and answer validation

## 1. 기본 원칙

- 질문과 선택지는 테스트 정의별로 관리한다.
- 질문 ID와 선택지 ID는 채점 규칙의 식별자로 사용한다.
- 이미지와 텍스트는 선택지를 표현하는 수단이다.
- 이미지 파일 자체는 점수 정보를 가지지 않는다.
- 서버는 고객이 제출한 답변을 검증한 후 저장한다.
- 고객이 제출한 점수는 신뢰하지 않는다.
- 내부 점수 규칙은 고객 API에 반환하지 않는다.

## 2. 질문 유형

질문별 선택 방식은 확정된 설계 자료를 기준으로 한다.

- 단일 선택: 허용된 선택지 중 정확히 하나를 선택
- 복수 선택: 허용 개수와 조합 규칙을 별도로 확인
- 비교 선택: 실제 제시한 비교쌍과 선택 결과를 보존
- 조건부 질문: 노출 조건과 응답 가능 조건을 확인

모든 질문이 위 유형을 반드시 사용한다고 가정하지 않는다.

## 3. 확인된 문항 예시

Simple Q10:
- 최종 전체 착장 선호를 관측한다.
- 이미지 선택지는 6개이다.
- 내부 선택지 코드는 A, B, C, D, E, F이다.
- 사용자는 정확히 하나를 선택한다.
- 선택지는 특정 RESULT 하나를 직접 의미하지 않는다.
- Q10 응답이 앞선 모든 응답을 덮어쓰지 않는다.

위 문항의 정보는 다른 질문에 자동 적용하지 않는다.

## 4. 답변 검증 원칙

- 요청 세션의 소유권을 검증한다.
- 세션에 배정된 질문인지 검증한다.
- 질문 정의에 존재하는 선택지만 허용한다.
- 질문별 선택 개수와 방식에 맞는지 검증한다.
- 비교형은 제시된 비교쌍과 응답이 일치하는지 검증한다.
- JSON null은 허용하지 않는다.
- 선택지 ID와 채점 규칙의 연결 무결성을 검증한다.
- 검증 실패 시 답변과 세션 revision을 변경하지 않는다.

## 5. 미확정 사항

- 모든 문항에 적용할 공통 JSON 필드 구조
- 복수 선택 문항의 허용 개수
- 비교형 답변의 정확한 데이터 표현
- 조건부 질문의 서버 검증 규칙
- Deep 전체 문항의 최종 선택지 규격

이 항목들이 확정되기 전에는 임의의 전역 답변 형식을 강제하지 않는다.

## 6. 개발 순서

1. 확정된 질문별 선택지 구조 확인
2. 질문 표시 데이터와 내부 채점 규칙 연결
3. 질문 유형별 답변 검증 구현
4. 잘못된 선택지와 선택 개수 거부 테스트
5. 점수 누적 및 RESULT 판정 구현
