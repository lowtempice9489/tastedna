# TasteDNA Scoring Contract

Status: DRAFT
Scope: Non-AI scoring engine

## 1. 기본 원칙

- 초기 TasteDNA는 AI 없이 결정적 규칙으로 동작한다.
- 텍스트 선택지와 이미지 선택지는 동일한 답변 처리 경로를 사용한다.
- 선택지의 표시 정보와 내부 채점 규칙은 분리한다.
- 클라이언트는 점수를 제출하지 않는다.
- 서버는 질문 ID와 선택지 ID를 검증한 후 채점한다.
- 이미지 교체만으로 선택지의 판별 의미가 바뀌어서는 안 된다.

## 2. 관측과 채점

- 선택지는 취향 항목에 긍정 또는 부정 증거를 제공할 수 있다.
- 모든 문항을 동일한 가중치로 처리한다고 가정하지 않는다.
- 비교형, 관계형, 조합형 관측은 필요에 따라 별도로 보존한다.
- 관계형 관측을 독립 속성 점수로 무조건 분해하지 않는다.
- 동일한 근거를 여러 취향 점수에 중복 반영하는 문제를 방지한다.
- 관측되지 않은 취향은 부정적인 취향으로 자동 해석하지 않는다.

## 3. 버전과 데이터 관리

- 테스트 정의는 scoringVersion을 가진다.
- 채점 규칙은 질문 표시 데이터와 분리하여 관리한다.
- 동일한 정의 및 채점 버전에서는 동일한 답변에
  동일한 채점 결과가 나와야 한다.
- 기존 세션의 채점 기준이 임의로 변경되지 않도록 한다.
- 채점 규칙은 고객용 질문 조회 API에 노출하지 않는다.

## 4. RESULT 판정

- 누적된 취향 관측을 RESULT 판정 근거로 사용한다.
- RESULT 판정은 관측된 증거를 기준으로 수행한다.
- 직접 관측하지 않은 취향 조합을 추측하여 확정하지 않는다.
- 25개 RESULT 후보를 모두 최종 확정된 유형으로 간주하지 않는다.
- 근거 부족, 판별 불가, 동점 상황의 처리 규칙은 별도로 설계한다.

## 5. 아직 확정하지 않은 사항

- 취향 항목의 최종 식별자와 저장 규격
- 선택지별 실제 가점 및 감점 수치
- 문항별 가중치와 정규화 공식
- 비교형 및 관계형 관측의 계산 규칙
- SIMPLE과 DEEP의 점수 통합 방식
- RESULT별 최종 판정 조건 및 동점 처리
- 점수 규칙을 저장할 DB 테이블의 상세 구조

## 6. 참고 설계

- TasteDNA 테스트 통합 설계 v0.1
- TasteDNA RESULT 설계 v1.0
- TasteDNA 질문·선택지 및 이미지 구성 통합 설계안 v0.2
- TasteDNA 제작 규칙 1

## 7. 점수 규칙 저장 구조의 설계 기준

- 채점 규칙은 서버 내부에서 버전별로 관리한다.
- 질문 표시 데이터와 채점 규칙은 별도로 저장한다.
- 채점 규칙은 scoringVersion과 연결되어야 한다.
- 선택지별 점수 규칙은 질문 ID와 선택지 ID를 기준으로 식별한다.
- 가점과 감점을 모두 표현할 수 있어야 한다.
- 비교형 및 관계형 관측은 단순 속성 점수와 구분하여 관리한다.
- 확정되지 않은 취향 항목이나 점수 범위는 임의로 정의하지 않는다.
- 기존 세션은 시작 당시의 채점 규칙을 재현할 수 있어야 한다.
- 채점 규칙의 변경이 기존 테스트 결과를 조용히 바꾸어서는 안 된다.
- 쇼핑몰별 규칙 조정이 가능하되 버전과 검증 절차를 갖추어야 한다.

## RESULT 후보 판별 목표

- 판별 대상은 25개 RESULT 후보를 기준으로 설계한다.
- Simple은 상대적으로 넓은 취향 방향을 파악한다.
- Deep은 더 세밀한 취향 관측으로 RESULT 후보를 좁힌다.
- Deep의 최종 RESULT 출력 목표는 최대 2개이다.
- 근거가 충분하지 않은 후보를 개수를 맞추기 위해 출력하지 않는다.
- 단순 누적 점수뿐 아니라 긍정·부정 증거, 비교 관측,
  RESULT 간 구별 가능성을 고려한다.
- 실제 판별 공식과 동점·불확실성 처리 기준은
  별도 검증 후 확정한다.
