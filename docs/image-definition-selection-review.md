# 이미지 Simple 정의 선택 검토 (14-T1)

현재 `td_test_definition`에는 모드·버전·활성 여부는 있지만 의류 범위와 이미지 테스트 구분 정보가 없다. V13 남성복과 V17 여성복은 모두 비활성이며, 모드별 활성 정의 조회는 기존 일반 시작 경로의 계약이다.

따라서 UUID를 버전 문자열, 접두사 검색 또는 최신 버전 정렬로 바꾸지 않았다. 그런 조회로는 새 세션에 사용할 승인된 정의를 유일하게 식별할 수 없다. 기존 UUID 기반 JPA 조회와 세션에 저장된 `definitionId`를 유지한다.

안전한 전환에 필요한 최소 계약은 **시작 경로별 현재 정의 지정**이다. 예를 들어 정의 테이블에 nullable·unique한 `start_key`를 추가하고, 남녀 이미지 Simple에 각각 하나의 시작 키를 부여하면 기존 JPA Repository에서 키로 유일 조회할 수 있다. 버전 정보는 정의 이력으로 유지하며 버전 문자열을 라우팅 규칙으로 해석하지 않는다.

이 방식을 채택한다면 후속 신규 마이그레이션에서 기존 남녀 정의에 키만 부여하고, Repository의 키 조회 및 누락 시 거부 테스트를 추가한다. 새 버전 전환은 트랜잭션 안에서 시작 키를 옮기며, 과거 정의·세션·답변의 ID는 변경하지 않는다. 기존 `active` 의미도 유지한다. 이번 작업에서는 스키마나 정의 데이터를 변경하지 않았다.
